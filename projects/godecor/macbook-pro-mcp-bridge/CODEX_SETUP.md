# Go Decor MacBook Pro → ChatGPT: задание для Codex

Дата подготовки: 2026-10-09. Проект: «Мастера Go Decor» / Hygge.
**Прочти весь документ, затем работай по этапам.** Ты — Codex, запущенный пользователем непосредственно на его MacBook Pro. Цель: создать надёжный **локальный MCP-сервер** на MacBook Pro и подготовить его к подключению в ChatGPT как пользовательский инструмент/плагин. На слабом VPS Hygge работают Home Assistant и прокси, поэтому на VPS **не ставить** AI-агентов, прокси, SDK, Docker-контейнеры или фоновые службы. MacBook Pro — исполнитель, VPS Hygge — лишь возможная цель SSH-диагностики.

## Результат, который нужен пользователю

После начальной настройки пользователь открывает ChatGPT (сначала **веб-интерфейс с поддержкой Plugins/Work**), подключает «Go Decor Mac Bridge», просит «проверь MacBook» и ChatGPT получает структурированный ответ непосредственно от MCP-инструмента, а не из GitHub. Когда позднее пользователь разрешит изменение файлов, мост сможет *ограниченно* инициировать задания Codex, с раздельными механизмами одобрения.

**Не обещай:** что конкретный Plus-аккаунт поддерживает запись через личные MCP-плагины или что такие плагины доступны прямо в Android Voice. Официальные описания пользовательских plugins и legacy developer mode сейчас отличаются. Проверь реальный UI и разрешения. Сначала проверяем из ChatGPT Work на web; для голоса отдельно тестируем поддержку инструментов. Ни при каких обстоятельствах не представляй «локально запустилось» как «ChatGPT успешно подключён».

## Непереговорные ограничения безопасности

- Никакого исполнения произвольной команды, которую прислал MCP-клиент; никаких инструментов `run_shell`, `exec`, `terminal`, произвольных SSH-команд, произвольного пути к файлу, `eval`/`subprocess(..., shell=True)` или эквивалентов. Не позволяй вводом пользователя выбирать внешний хост или исполняемый бинарник.
- Не открывай порт MacBook на внешних интерфейсах, не выключай macOS Firewall/Gatekeeper/SIP, не открывай порты на VPS. MCP слушает **только `127.0.0.1`**.
- Удалённое подключение **только через защищённый исходящий туннель** с контролем доступа; **предпочтительно OpenAI Secure MCP Tunnel**. Если не удаётся настроить доказуемо защищённую авторизацию или недоступны необходимые права на туннель, останавливай удалённую публикацию и оставляй полностью рабочую локальную установку с ясным отчётом. Никогда не используй публичный anonymous tunnel для приватной диагностики.
- Никогда не показывай, не печатай и не коммить секреты, содержимое `~/.ssh
