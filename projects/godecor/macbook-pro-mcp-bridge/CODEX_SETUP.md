# Go Decor — MacBook Pro как MCP-инструмент ChatGPT
## Полное техническое задание для Codex

Дата: 9 октября 2026 года. Проекты: Go Decor / Hygge.
Назначение: **выполнять это задание непосредственно в Codex на MacBook Pro**.

Ты — Codex CLI, запущенный владельцем локально на MacBook Pro. Твоя задача — **создать и проверить работающий MCP Bridge**, через который ChatGPT сможет вызывать ограниченные инструменты MacBook Pro, а позднее, после отдельной настройки разрешений, поручать Codex работу с проектами и проверять VPS Hygge по SSH.

**Это задача на реальную реализацию, а не на написание плана.** Самостоятельно проведи диагностику, создай проект, исходный код, тесты, служебные скрипты, автозапуск и подробный отчёт. Если конкретный этап упирается в логин, права платформы, отсутствие функции в тарифе, отсутствие доступа к интернету или физическое подтверждение на Mac, останови только заблокированный этап, объясни действие владельцу и продолжай независимые этапы.

### Целевое поведение

В ChatGPT пользователь говорит: «Проверь состояние MacBook Pro». ChatGPT вызывает инструмент bridge_ping или mac_health и в рамках того же запроса получает свежие показатели MacBook. Позже: «Проверь VPS Hygge» — инструмент на Mac выполняет разрешённую диагностику VPS по существующему SSH-доступу. В будущем: «Пусть Codex исправит приложение» — мост создаёт ограниченное задание, проверяет разрешения и после подтверждения выполняет работу в выделенном каталоге.

**Не путай этапы**:
- LOCAL_OK — локальный MCP-сервер реально запущен и протестирован.
- TUNNEL_OK — безопасная удалённая связь через OpenAI Secure MCP Tunnel установлена.
- CHATGPT_OK — инструмент реально был вызван из ChatGPT и вернул ответ.
- VOICE_OK — инструмент действительно вызван именно из требуемого голосового режима.
- HYGGE_SSH_OK — фактическая безопасная SSH-диагностика VPS с Mac.

Проверка одного статуса не означает успех остальных. Ничего не объявляй успешным без теста.

### Исходные ограничения и архитектура

MacBook Pro — постоянно работающий исполнитель; VPS Hygge слабый, уже занят Home Assistant и прокси. **Ничего не устанавливай и не запускай на VPS**: на нём нужны только уже существующий sshd и разрешённые диагностические команды по SSH. Пользователь также имеет MacBook Air, но на первом этапе его не настраиваем.

Цепочка должна быть такой:

  ChatGPT → подключённый личный MCP plugin → OpenAI Secure MCP Tunnel →
  tunnel-client на MacBook Pro → MCP-сервер на 127.0.0.1 → инструменты диагностики
                                                         ↘ SSH к VPS Hygge

GitHub **не** используется для очереди заданий. Храни в Git лишь код и документацию, никаких ключей. В отличие от GitHub-поллера, запрос MCP будет обрабатываться как инструмент во время активного обращения ChatGPT. Это НЕ означает, что ChatGPT самостоятельно просыпается и пишет в уже завершённый разговор.

**Рекомендованный транспорт: OpenAI Secure MCP Tunnel**, поскольку он инициирует исходящие HTTPS-соединения с Mac, без открытия на нём публичного входящего порта. Для его работы могут потребоваться отдельные права OpenAI Platform и API-ключ. Наличие ChatGPT Plus не гарантирует доступа к созданию custom MCP plugin, read/write tools, Tunnel или вызовам из Voice. Сначала фактически проверь доступность соответствующих пунктов интерфейса. Если функция недоступна на аккаунте, продолжи локальный прототип и честно сообщи BLOCKED_BY_PLAN_OR_UI. Ничего не обходи.

## Шаг 1. Аудит Mac без изменений системы

Собери и занеси в SETUP_REPORT.md:
- macOS version (sw_vers), архитектуру (uname -m), доступное место и оперативную память;
- версии/наличие python3, node, npm, git, brew, codex, ssh;
- доступность исходящего HTTPS и HTTPS к api.openai.com:443;
- где можно создать отдельный рабочий каталог; какие существующие SSH host aliases есть **без раскрытия секретов**;
- ограничения macOS и sleep/power (Mac должен оставаться включённым);
- достаточность версии Python или Node для SDK; не обновляй macOS без согласия.

Не выводи в лог или чат содержимое ~/.ssh, ~/.codex/auth.json, токены, API keys, приватные ключи, cookie или переменные окружения с секретами. Не печатай серийный номер Mac.

## Шаг 2. Создай рабочий проект

Создай ~/godecor-mac-bridge (если уже существует, не перезаписывай без сверки). Это самостоятельный репозиторий/папка, не затрагивающая существующие приложения.

В проекте должны появиться:
- исходный код MCP-сервера;
- зафиксированные версии зависимостей и воспроизводимая установка в собственном venv;
- README.md, SECURITY.md, .gitignore, пример конфигурации без секретов;
- автоматические тесты и сценарий сквозного тестирования MCP;
- scripts/install, scripts/start, scripts/stop, scripts/status, scripts/doctor, scripts/uninstall;
- шаблон launchd LaunchAgent plist и SETUP_REPORT.md.

Все скрипты должны работать повторно без повреждения данных. Никакого sudo, кроме случая, когда действительно необходимо и пользователь явно подтвердил операцию.

## Шаг 3. Реализуй настоящий локальный MCP-сервер

Транспорт: Streamable HTTP на **127.0.0.1** с endpoint /mcp, без слушания на 0.0.0.0 и без публичного порта. Подбери свободный фиксируемый порт, запиши его в локальный конфиг. Обеспечь корректный MCP initialize и tools/list, типизированные схемы параметров, аннотации readOnly/destructive/openWorld согласно спецификации, таймауты и ограниченный JSON-вывод.

В версии 1 должны быть эти реальные MCP tools:
1. bridge_ping(): версия bridge, время, uptime, instance ID (случайный ID, не персональный), результат «alive».
2. mac_health(): версия macOS, CPU architecture, общий статус CPU/RAM/disk, uptime, статус службы. Без содержимого файлов и персональных путей.
3. codex_health(): установлен ли Codex CLI, версия и безопасная проверка доступности; никогда не выдавай токены и не запускай произвольный промпт.
4. bridge_capabilities(): список реально реализованных функций и ограничений; версия 1 — read-only.
5. hygge_ssh_health(): только после локальной установки/проверки точного SSH alias; заранее заданные read-only команды (например uptime, df на выбранном разделе, ограниченное состояние контейнеров при наличии прав). Никакого пользовательского параметра для произвольной SSH-команды, хоста, имени бинарника, пути или shell.

Обработка SSH: существующие ключи в ~/.ssh, строгая проверка host key, BatchMode=yes, короткий ConnectTimeout, отсутствие TTY, фиксированный allowlist операций и принудительные лимиты вывода. Если SSH недоступен — вернуть NOT_CONFIGURED, SSH_AUTH_FAILED или TIMEOUT вместо придуманных данных. Никогда не отправлять секреты на MCP-клиент.

**Запрещено** создавать инструменты общего назначения run_shell, execute_command, arbitrary_python, change_file, raw_ssh или shell=True. Запрос ChatGPT не должен превращаться в свободную команду на Mac. Не запускать команды с root, не изменять конфигурацию Home Assistant и прокси, не делать reverse SSH с VPS.

## Шаг 4. Безопасность и тесты

Сервер выполняется от текущего пользователя, не root; рабочая директория изолирована; секреты в системном защищённом хранилище или локальных chmod 600 файлах вне git; входные параметры валидируются; максимальная длина ответов и таймауты конечны; минимум прав; нет доступа к произвольным файлам; нет раскрытия переменных окружения.

Используй официальный MCP Inspector и автоматические тесты:
- успешные initialize/tools/list и каждый tool;
- ошибки SSH, отсутствующего Codex и таймауты;
- неверные параметры и повторяющиеся запросы;
- попытка запросить произвольную shell-команду и чтение секретного файла — отклоняются;
- ложные статусы запрещены, ошибки возвращаются безопасно;
- невозможно подключиться к MCP-сокету через внешний IP интерфейса Mac.

Фиксируй PASS/FAIL по каждому тесту в отчёте, не объявляй тесты пройденными только потому, что исходники созданы.

## Шаг 5. Автозапуск macOS

Подготовь пользовательский LaunchAgent в ~/Library/LaunchAgents, используй launchd с KeepAlive/RunAtLoad, явные абсолютные пути и короткий PATH. Дай команды безопасного запуска, остановки, статуса, просмотра редактированных логов, повторной установки и удаления. Исключи бесконечный crash-loop, не сохраняй в логах секреты. Проверь перезапуск после падения приложения.

Для круглосуточной работы Mac должен быть на питании и не переходить в sleep. Проверь настройки и предложи владельцу допустимую конфигурацию. **Не меняй глобальные настройки питания без его разрешения**; закрытая крышка ноутбука может приводить к сну даже при включённом LaunchAgent. Не отключай системные защиты.

## Шаг 6. Secure MCP Tunnel — предпочтительный канал

Доступ к платформенным туннелям и ChatGPT Plugins — две разные проверки. Уточни наличие:
- прав Tunnels Read + Manage для создания Tunnel;
- прав Tunnels Read + Use для запуска tunnel-client и выбора туннеля;
- tunnel_id, связанного с нужным ChatGPT workspace;
- runtime API key для tunnel-client, вводимого владельцем ЛОКАЛЬНО;
- пользовательского права Add custom MCP server в ChatGPT Plugins.

Инструкции только из официальных docs и проверенного релиза tunnel-client. Настрой туннель, направляющий запросы на локальный MCP endpoint. Сначала tunnel-client doctor --profile <имя> --explain, затем реальный запуск, проверка readyz/healthz и связи с MCP. Аутентификация и права должны быть проверены фактически. Не помещай ключи, tunnel credentials и приватные адреса в GitHub или отчёт, который будет опубликован.

Если OpenAI Tunnel недоступен: оставь рабочий локальный MCP. Альтернативой может быть HTTPS reverse tunnel, но только с настоящей проверенной OAuth 2.1 авторизацией, валидацией токена на каждом вызове, правильными audience/issuer/scope и TLS. **Никогда не публикуй приватный Mac MCP как анонимный публичный URL**. Обычный публичный туннель без авторизации недопустим.

## Шаг 7. Подключение в ChatGPT

После LOCAL_OK и TUNNEL_OK дай владельцу короткую инструкцию:
1. Открыть https://chatgpt.com/plugins в браузере.
2. Найти плюс → Add custom MCP server. Если пункта нет, отметить BLOCKED_BY_PLAN_OR_UI, а не симулировать успех.
3. Создать приватный Go Decor Mac Bridge, в Connection выбрать Tunnel и tunnel_id, выбрать требуемую авторизацию. Альтернатива — только защищённый HTTPS /mcp, если tunnel недоступен.
4. Установить получившийся plugin.
5. Открыть ChatGPT Work в web, выбрать plugin через @ и запросить bridge_ping, затем mac_health.
6. Отдельно попробовать нужный голосовой режим на Android. Если plugin не доступен там, VOICE_OK=BLOCKED/NOT_TESTED: подключение из ChatGPT Work само по себе не доказывает доступность в Voice.

ChatGPT_OK отмечай только после фактического успешного удалённого MCP-вызова. VOICE_OK — только после вызова именно из голоса.

## Шаг 8. Подготовь второй этап: задачи Codex, но НЕ включай их удалённо

Владелец хочет, чтобы по дальнейшим поручениям ChatGPT MacBook мог запускать Codex для разработки Go Decor и подключаться к Hygge. Создай файл FUTURE_CODEX_JOBS.md с проектом механизма задач:
- выделенный allowlist каталогов/репозиториев, без произвольных путей;
- инструменты propose_codex_job, get_job_status, get_job_result, cancel_job;
- новая задача по умолчанию лишь proposed; её исполнение — после отдельного, проверяемого локального разрешения владельца и server-side policy;
- очередь, отдельные рабочие каталоги, уникальный job ID, журнал без секретов, ограничение времени/ресурсов, лимит вывода, sandbox для Codex, запрет небезопасных флагов;
- для mutating operations — отдельные разрешения и инструменты с минимальными полномочиями;
- никакого произвольного remote shell, даже если ChatGPT настойчиво просит его включить;
- не считать подтверждения в ChatGPT достаточными без независимой проверки политики/разрешений на Mac.

**В первой версии не выставлять write-tools на внешнее MCP соединение.** Сначала добейся надёжного чтения состояния Mac и проверки связи.
