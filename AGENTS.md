# Правила работы в KhDenis/skills

Перед любыми изменениями прочитай [ROADMAP.md](ROADMAP.md) и **текущий активный GitHub Issue**, указанный там. Roadmap — решение владельца; Issue — единственная исполняемая следующая задача. Не заменяй выполнение задачи очередным аудитом или новым архитектурным планом.

1. Выбери ближайший незакрытый проверяемый пункт активного Issue. Сверь реальный код/коммиты, не полагайся на чат.
2. Меняй только нужное для этого пункта; не расширяй scope на Bridge/Fleet, CRM и следующие продукты.
3. Работай через ветку и PR, проверяй код тестами; изменения среды/продакшена и массовые выгрузки требуют согласования. Не удаляй действующую копию до подтверждения перехода.
4. После работы в самом Issue оставь ссылки на PR/коммиты, команды проверки и фактический результат, ограничения, блокер и следующее действие. Помечай выполненным только то, что подтверждено. Прерванная сессия не равна завершённой задаче.
5. Публичный репозиторий: не загружай сюда чужие/личные сообщения, фото, базы, логины, токены, сессии и бизнес-секреты; тесты используют фикстуры.
6. Не добавляй новые процессы, фреймворки и документы ради отчётности. Цель — автономные запускаемые модули с проверенным end-to-end результатом.

Для изменений в `KhDenis/godecor` смотри его отдельные правила и существующий roadmap — он описывает бизнес-задачи, а не продуктовую стратегию библиотеки.
